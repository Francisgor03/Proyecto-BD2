# AgroSmart – Parte Oracle: guía de instalación

> **Estado:** los scripts están escritos pero **no se han ejecutado contra un Oracle real** (no tuve acceso a uno). Los datos sí se validaron con un script de Python que replica las restricciones (unicidad, llaves foráneas, fechas, mínimo 30 filas). Si algún script da error, copia el mensaje exacto y se corrige.
> Todos los datos son **sintéticos**. Los scripts no llevan tildes a propósito, para que SQL Developer no muestre caracteres raros.

## Requisitos
- Oracle Database 12c o superior (por las columnas *identity*). Si usas Oracle XE 21c, el servicio es `XEPDB1`.
- SQL Developer.

## Archivos y orden de ejecución

| Orden | Archivo | Conectado como | Qué hace |
| --- | --- | --- | --- |
| 1 | `00_usuarios.sql` | SYSTEM (servicio XEPDB1) | Crea los usuarios `agrosmart_owner`, `agrosmart_app`, `agrosmart_lector` y el rol `agrosmart_app_rol` |
| 2 | `01_creacion_tablas.sql` | AGROSMART_OWNER | Crea las 10 tablas, restricciones, índices y la vista `v_costo_campania` |
| 3 | `02_datos_oracle.sql` | AGROSMART_OWNER | Inserta los datos sintéticos (≥ 30 filas por tabla) |
| 4 | `05_seguridad.sql` | AGROSMART_OWNER | Otorga permisos al rol de la aplicación y al lector |
| 5 | `03_consultas.sql` | AGROSMART_OWNER | Consultas SELECT, JOIN, agregaciones y validación de reglas |
| 6 | `04_crud.sql` | AGROSMART_OWNER | Ejemplos de INSERT, UPDATE, DELETE y pruebas de integridad |
| – | `99_limpieza.sql` | AGROSMART_OWNER | Borra todo para repetir la instalación |

Otros: `generar_datos_oracle.py` (regenera los datos; semilla fija), `datos_oracle/*.csv` (los mismos datos en CSV) y `referencia_mongo.json` (para quien hace MongoDB).

## Pasos en SQL Developer
1. **Conexión como SYSTEM:** nueva conexión → usuario `SYSTEM`, host `localhost`, puerto `1521`, **Nombre de servicio** `XEPDB1` (no SID `XE`). Abre `00_usuarios.sql`, **cambia las contraseñas** y ejecútalo con **F5** (Run Script).
2. **Conexión como dueño:** nueva conexión con `agrosmart_owner` y la contraseña que pusiste (mismo servicio). Ejecuta con **F5**, en este orden: `01`, `02`, `05`.
3. **Verifica:** ejecuta la consulta 1 de `03_consultas.sql`; deben salir 30, 35, 30, 40, 40, 83, 30, 63, 91 y 40 filas (según la semilla 2026).
4. **Seguridad:** conéctate como `agrosmart_lector` y `agrosmart_app` y haz las pruebas que están comentadas al final de `05_seguridad.sql`. Captura las pantallas.

## Errores frecuentes
- `ORA-65096: invalid common user or role name`: estás conectado a la raíz (CDB). Usa el servicio `XEPDB1`.
- `ORA-01950: no privileges on tablespace USERS`: falta la cuota; revisa `00_usuarios.sql`.
- `ORA-00955: name is already used`: ya existe el objeto; usa `99_limpieza.sql` y repite.
- Si `GENERATED BY DEFAULT AS IDENTITY` da error, tu Oracle es anterior a 12c: avísame y lo adapto con secuencias.

## Detalles de diseño
- Los ids de los datos van del 1 al N. Las tablas usan *identity* con `START WITH 1000`, así que los registros que cree la aplicación empiezan en 1000 y no chocan.
- La regla RN-03 (sin campañas solapadas en una parcela) y RN-04 (fechas dentro de la campaña) no son restricciones declarativas: se validan en la aplicación Python. En `03_consultas.sql` hay consultas que comprueban que los datos las cumplen (deben devolver 0 filas).
- Para Python: cadena de conexión `localhost:1521/XEPDB1`, usuario `agrosmart_app`, contraseña en una variable de entorno. Las tablas son del esquema `AGROSMART_OWNER`: usa `ALTER SESSION SET CURRENT_SCHEMA = AGROSMART_OWNER` o el prefijo del esquema.
